## 3단계: 계정 조치 (클라우드 브라우저)
원칙: AI가 모든 사이트를 알아서 처리하지 않는다. **서비스별 흐름**을 먼저 정의하고, 없는 곳은 직접 처리 안내.

- [x] 흐름 정의 형식 (`backend/actions/flows.py`): goto / click / fill / user / confirm / expect
- [x] 실행기 (`backend/actions/runner.py`): Playwright(Chromium) 헤드리스, 작업마다 새 시크릿 컨텍스트 후 폐기
  - DOM(글자·선택자) 우선 → 못 찾으면 AI 스크린샷 보조(키가 있을 때) → 그래도 없으면 사용자에게 넘김
- [x] 원격 화면: 1초마다 스크린샷, 클릭·글자·키(Enter/Tab/Backspace 등 허용 목록)·스크롤 전달
- [x] API: `POST /api/actions`, 상태, 화면, 입력(resume/confirm/cancel 포함), 조치 기록
- [x] 프론트: 정리하기·정리 내역을 실제 에이전트로 (목업 모드는 시뮬레이션 유지)
  - 입력 필요 → 원격 화면, 확인 필요 → 확정/취소, 에이전트 실패 → 직접 처리 전환 + 이용권 환불
- [x] 자동화 가능 여부는 검증된 흐름이 있는 서비스만 "대신 처리"
- [x] 실행기 검증용 데모 서비스 (`/demo`: 로그인 → 마이페이지 → 탈퇴). `IDLY_DEMO=1`이면 보고서에 체험 계정
- [x] 조치 기록(감사 로그) `action_log`: 시작·입력 요청·확인 요청·확정·완료·실패·취소
- [ ] AI 스크린샷 보조: 실제 사이트에서 정확도 확인 (코드는 있음, 데모에서는 쓰일 일이 없음)
- [ ] (검증) 첫 실제 서비스 흐름 3~5개: 실제 계정으로 선택자 확인 후 `verified: True`
- [ ] 에이전트 작업은 서버 메모리에만 있음 → 서버 재시작 시 진행 중 작업 사라짐 (작업 큐·워커 분리 필요)
- [ ] 원격 화면 품질: 스크린샷 폴링(1초) → WebSocket·CDP screencast로 개선
