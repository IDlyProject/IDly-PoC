## 1. 제품

IDly(아이들리): 이메일에 흩어진 가입·인증·결제·로그인 기록으로 내 온라인 계정과 구독을 찾고, 탈퇴·구독 해지·권한 해제까지 대신 처리하는 개인용 계정 관리 AI 에이전트.

핵심 흐름 (사업계획서)

1. 이메일 연동 및 계정 탐색
2. 계정 현황 보고서
3. 정리할 계정 선택
4. 계정 정리 자동화 (탈퇴·결제 변경 등 중요한 단계는 사용자 최종 확인)

과금: 첫 계정 현황 보고서 + 계정 정리 1회 무료, 이후 계정 정리 5회 2,900원.

## 5. PM 검토 반영 (화면 기획)

| 검토에서 나온 문제                                | 화면 반영                                                                                                 |
| ------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| 앱 비밀번호 준비 과정에서 연동 이탈               | 연동 화면에 서비스별 준비 체크리스트 + 예상 소요 시간                                                     |
| 탐색이 수 분~수십 분 걸리는데 화면이 몇 초를 전제 | 예상 소요 시간 안내. 탐색이 끝나야 보고서로 이동 (중간에 둘러보기는 제거)                                 |
| 추출 정확도가 낮으면 신뢰 붕괴                    | 계정마다 근거 메일 수 표시, "내 계정이 아니에요" 숨김 + 되돌리기 (정확도 측정에도 사용)                   |
| 자동화가 막히면 이용권 가치가 사라짐              | 자동 대행 / 직접 처리 안내로 분리. 대행한 계정만 이용권 차감, 직접 처리 무료, 대행 포기·탈퇴 취소 시 환불 |
| 보고서는 추천만 보여주고 담기는 하나씩            | "추천 조치 n개 모두 담기"                                                                                 |
| 로그인·본인인증에서 자동화가 멈춤                 | 정리 내역에 "지금 할 일" 모음: 입력 필요(원격 브라우저), 탈퇴 최종 확인, 직접 처리                        |

화면 밖에서 검증할 것 (검토 결과): 연동 5명 관찰 테스트, 상위 20개 서비스 탈퇴·해지 수동 조사, 이용권 결제 버튼 fake door, 팀원 메일함 추출 정확도.

## 6. 결정이 필요한 것 (요구사항끼리 부딪히는 지점)

1. **웹 백엔드 vs 설치형**
   - 브라우저는 IMAP에 직접 접속할 수 없으므로 웹 백엔드가 IMAP을 대신 받는다.
   - 이 구조는 다운로드 없이 여러 IMAP 도메인을 지원하지만, 메일이 사용자 PC 밖으로 나간다.
2. **OpenAI API로 분석**
   - 서버에서 민감정보를 마스킹한 뒤 OpenAI API로 보낸다. 개인정보 국외 이전 동의와 삭제 정책이 필요하다.
   - Gmail API Restricted Scope 대신 앱 비밀번호 IMAP을 쓰면 CASA 대상 경로를 줄일 수 있지만, 공개 출시 전 법무·보안 검토는 별도다.
3. **클라우드 브라우저 대행**
   - 사이트 로그인 세션이 우리 서버의 브라우저를 거친다. 메일(CASA)과는 무관하지만, 계정 세션을 다루므로 보안·약관 검토가 필요하다.
